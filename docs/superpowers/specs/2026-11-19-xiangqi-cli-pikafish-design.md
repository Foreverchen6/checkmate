# 文字版中国象棋陪练（Node/TS + Pikafish）设计文档

- 日期：2026-11-19
- 状态：待评审
- 目标读者：实现者（本人）

## 1. 背景与目标

用户希望通过文字界面对弈中国象棋，并借助 AI 对手提升自己的棋力。AI 本身不需要训练，训练对象是人：核心闭环是“对弈 → 赛后复盘 → 针对性改进”。

第一版目标：

1. 终端中以中文棋子字符展示棋盘，完成一整局合法对弈。
2. 由 Pikafish 提供陪练 AI，三档难度可选。
3. 每局结束后逐手复盘，标出失误/漏着并给出引擎推荐着法。
4. 对局棋谱落盘，便于日后用其他软件复盘。

## 2. 范围

### 做

- 单机终端 CLI，人机对弈（人执红或黑）
- 完整走法合法性与终局判定
- 中文记谱与 UCI 坐标双输入
- Pikafish UCI 接入、三档难度、提示与悔棋
- 赛后逐手复盘报告
- 棋谱 JSON 落盘

### 不做

- 联网、多人对战、观战
- Web / GUI 界面
- AI 自对弈训练、模型训练
- 开局库、云库查询
- 跨局战绩统计与进步曲线
- 复杂长将裁决、完整的象棋竞赛规则例外条款

## 3. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js 24（原生执行 TS） | 零构建步骤，运行时零依赖 |
| 开发依赖 | `typescript`、`vitest` | 仅类型检查与测试 |
| AI 引擎 | Pikafish 2026-09-25（UCI 协议） | 开源、棋力强、复盘准确；已实测握手与 NNUE 加载 |
| 存储 | 本地 JSON 文件 | 单机场景足够，无需数据库 |

Pikafish 二进制与 NNUE 权重是第一期运行的**硬依赖**，当前已位于项目根目录：

- `Pikafish-Windows-x86-64-universal.exe`
- `pikafish.nnue`（约 50.7 MB）

开发、测试、验收一律使用真实引擎，不提供桩引擎、模拟引擎或降级运行路径。运行时通过 `config.json` 或环境变量覆盖路径。

## 4. 架构

```
src/
  main.ts        CLI 入口：参数解析、启动检查、对局循环
  rules/         棋盘模型、FEN、走法生成、合法性、终局判定
  notation/      UCI 坐标 ↔ 内部坐标 ↔ 中文记谱
  render/        中文棋子 ASCII 棋盘渲染
  engine/        Pikafish UCI 子进程封装、难度档位
  game/          对局状态机：落子、历史、悔棋、结果
  review/        逐手分析、失误分级、报告生成
  storage/       棋谱序列化与落盘
tests/           与 src 对应的单元/集成测试
```

依赖方向单向：

- `rules` 不依赖引擎、终端、文件系统，全部为纯函数
- `engine` 只接受 FEN 与节点限制，返回着法与评分
- `review` 复用 `engine`
- `game` 依赖 `rules`，不依赖 `engine`（AI 应招由 `main` 协调）
- `main` 是唯一同时接触终端 IO、引擎与存储的模块

核心数据流：

```
输入(中文/坐标) → rules 校验 → game 落子 → render → 终局判定
                                              ↓
                                engine 计算应招 → game 落子 → render
```

## 5. 规则引擎

### 5.1 棋盘表示

- 9 列 × 10 行，内部坐标 `file ∈ [0,8]`（a–i）、`rank ∈ [0,9]`（红方底线为 0）
- 渲染时棋子为全角汉字，按每个棋子占 2 个终端列计算宽度，避免 CJK 字符导致棋盘错位
- 棋子编码采用 Pikafish 接受的 FEN 字母：`K/A/B/N/R/C/P` 为红（`B` 象、`N` 马），小写为黑
- 注意：Pikafish 2026-09-25 不接受把马写成 `H`、象写成 `E`，会报 `Invalid FEN`
- 初始 FEN：

```
rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1
```

### 5.2 走法规则

必须正确实现：

- 车/炮：直线移动；炮吃子必须恰好隔一个炮架
- 马：日字，绊马腿
- 相/象：田字，塞象眼，不可过河
- 士/仕：九宫内斜走一步
- 将/帅：九宫内直走一步；禁止将帅同列且中间无子（照面）
- 兵/卒：未过河只可前进；过河后可前进或横走；不可后退

### 5.3 合法性

一步棋合法当且仅当：

1. 符合该棋子的走法；
2. 落点不是己方棋子；
3. 走完后己方将/帅不被将军，且不出现将帅照面。

### 5.4 终局判定

| 情况 | 结果 |
|---|---|
| 对方被将军且无合法应着 | 将死，己方胜 |
| 对方未被将军但无合法着法 | 困毙，对方负 |
| 连续 120 个半回合（60 回合）无吃子 | 和棋 |
| 同一局面（含行棋方）第三次出现 | 和棋 |
| 用户 `resign` | 对方胜 |
| 用户 `quit` | 对局中止，保存棋谱 |

明确简化：长将、长捉等按“三次重复判和”处理，不实现“长将判负”的完整裁决。

## 6. 记谱

### 6.1 UCI 坐标

形如 `h2e2`，小写字母为列、数字为行，行号以红方底线为 0。同时接受 `h2-e2` 写法。

### 6.2 中文记谱

红方用汉字数字、黑方用阿拉伯数字；列号各自从本方右侧起算。

- 动作：`进` / `退` / `平`
- 直行棋子（车炮兵将）：进/退后跟移动格数
- 斜行棋子（马相士）：进/退后跟目标列号
- `平` 后跟目标列号
- 同列同种棋子：两子用 `前`/`后`；三子用 `前`/`中`/`后`；四子及以上按 `前`/`二`/`三`/…/`后` 编号

实现策略：不手写反向解析器。先生成全部合法着法的中文记谱，再把用户输入规范化后与生成结果精确匹配。这样“前炮/后炮”、多兵同列等歧义由生成逻辑自然消解。

若输入无法匹配且存在多个相似候选，列出候选供用户选择。

## 7. 引擎集成

### 7.1 生命周期

启动时 spawn Pikafish 子进程并完成握手：

```
uci            → uciok
setoption name EvalFile value <nnue 路径>
setoption name Threads value <n>
setoption name Hash value <mb>
isready        → readyok
```

每步只发送 `position fen <fen>` + `go nodes <N>`。收到 `bestmove` 后解析 `info ... score cp|mate ... pv ...`。

已用项目内的 2026-09-25 版本实测：`uci` 输出包含 `EvalFile`、`Threads`、`Hash`、`MultiPV`、`Skill Level` 等选项；指定 `pikafish.nnue` 后 `isready` 返回 `readyok`。启动校验以此为准。

### 7.2 难度档位

| `--level` | 档位名 | 节点数 | 附加行为 |
|---|---|---|---|
| 1 | `beginner`（新手） | 2,000 | MultiPV=3，按评分加权随机选择 |
| 2 | `entry`（入门） | 20,000 | 直接取最佳着法 |
| 3 | `intermediate`（中等） | 200,000 | 直接取最佳着法 |

节点数而非时间控制，保证同一局面结果可复现。棋谱中的 `difficulty` 字段记录档位名。

### 7.3 复盘强度

- 固定 300,000 节点、MultiPV=1
- 提示（`hint`）使用 200,000 节点

### 7.4 评分视角

UCI 评分以“行棋方”为正方向。展示与复盘统一换算为红方视角；将杀用 `mate N` 表示，并视为 ±∞ 参与比较。

### 7.5 超时与崩溃

- 单次计算超时（默认 15 秒）时终止当前搜索，报告并让用户选择重试或退出
- 引擎进程异常退出时保存当前棋谱，给出错误信息
- 启动时必须完成 `isready` 握手，验证 NNUE 已加载；二进制缺失、权重缺失或握手失败都直接退出，不允许在无引擎状态下进入对局

## 8. 对局流程

```
启动 → 读取配置 → 校验引擎 → 选择先后手与难度
  → 循环：
      渲染棋盘
      人类输入（着法 / hint / undo / resign / quit）
      校验并落子
      终局判定
      引擎应招并落子
      终局判定
  → 询问是否复盘 → 输出报告
  → 落盘棋谱
```

- 默认人执红先行；`--side black` 执黑
- `undo` 回退人类上一步与 AI 应招（共两步）；若 AI 尚未应招则只回退一步
- 每次落子后立即写入内存历史，退出或崩溃时仍可保存棋谱

## 9. 复盘

对人类的每一手：

1. 分析落子前局面，得到最佳着法与评分（行棋方视角）
2. 分析落子后局面并取反，得到实际着法评分
3. 计算 centipawn loss = 最佳评分 − 实际评分，下限 0

分级：

| 损失（cp） | 标签 |
|---|---|
| < 20 | 好棋 |
| 20–49 | 可接受 |
| 50–149 | 失误 |
| ≥ 150 | 漏着 |

补充规则：

- 最佳着法为将杀而实际不是，一律记为漏着
- 实际着法被将杀，一律记为漏着

报告内容：

- 逐手列表：回合、你的着法、引擎推荐、损失、标签
- 推荐着法后的变化主线（最多 6 个半回合，转为中文记谱）
- 汇总：失误数、漏着数、平均损失（ACPL）
- 损失最大的 3 手单独列出，作为改进重点

## 10. 棋谱存储

目录：`records/`，文件名 `YYYY-MM-DD-HHmmss.json`。

```json
{
  "version": 1,
  "startedAt": "2026-11-19T10:30:45+08:00",
  "humanSide": "red",
  "difficulty": "entry",
  "result": "black_win",
  "endReason": "checkmate",
  "initialFen": "rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1",
  "finalFen": "...",
  "moves": [
    { "ply": 1, "side": "red", "uci": "h2e2", "chinese": "炮二平五" },
    { "ply": 2, "side": "black", "uci": "h7e7", "chinese": "炮8平5" }
  ]
}
```

- `result` 枚举：`red_win` / `black_win` / `draw` / `aborted`
- `endReason` 枚举：`checkmate` / `stalemate` / `move_limit` / `repetition` / `resign` / `aborted`
- 按用户要求，只保存棋谱本身，不保存复盘报告与跨局统计

## 11. CLI 与配置

### 11.1 用法

```
node src/main.ts [--side red|black] [--level 1|2|3] [--config ./config.json] [--no-review]
```

- `--level` 默认 2（入门）
- 对局结束后默认询问是否复盘；`--no-review` 跳过询问

### 11.2 配置

`config.json`：

```json
{
  "pikafishPath": "./Pikafish-Windows-x86-64-universal.exe",
  "evalFile": "./pikafish.nnue",
  "threads": 1,
  "hashMb": 64
}
```

优先级：命令行 `--config` 指定文件 > 当前目录 `config.json`；加载文件后，环境变量 `PIKAFISH_PATH` / `PIKAFISH_EVAL_FILE` 再覆盖其中的对应字段。

## 12. 错误处理

| 场景 | 行为 |
|---|---|
| 非法走法 | 提示原因，状态不变，重新输入 |
| 中文记谱无法匹配 | 提示格式，若存在相似候选则列出 |
| 引擎/权重文件缺失 | 打印配置指引后退出（退出码 1） |
| 引擎握手失败或超时 | 报错并退出，不进入对局 |
| 引擎应招超时 | 提示并让用户选择重试或中止 |
| 引擎返回非法着法 | 视为引擎错误，保存棋谱并退出 |
| 棋谱写入失败 | 在终端打印完整 JSON 作为兜底 |

## 13. 测试策略

- 规则单测：每种棋子的合法/非法走法；马腿、象眼、炮架、九宫、过河兵、照面
- 局面单测：将军、将死、困毙、60 回合和棋、三次重复
- 记谱回环：随机合法局面上，生成中文记谱再匹配回原着法
- FEN 回环：解析→序列化结果一致
- 复盘分级：构造不同损失值验证阈值与失杀特判
- UCI 解析器：用真实引擎输出的固定样本测试 `info`/`bestmove` 解析，覆盖异常行与超时处理
- 集成测试：默认启动项目根目录的真实 Pikafish，完成握手、加载 NNUE、搜索并返回合法着法；引擎或权重缺失时测试直接失败，不使用桩替代

## 14. 里程碑

1. 规则内核：棋盘、FEN、走法生成、合法性、终局判定 + 单测
2. 渲染与记谱：中文棋盘、中文/UCI 互转 + 单测
3. 引擎适配：UCI 子进程封装 + 真实引擎握手与搜索测试
4. 对局闭环：CLI 循环、hint/undo/resign、AI 应招
5. 复盘与存储：逐手分析、报告、棋谱落盘
6. 完整对局验收：真实引擎下完一局并检查复盘质量

## 15. 风险与取舍

- **Pikafish 版本差异**：当前锁定 2026-09-25 并已实测。启动时仍解析 `uci` 输出校验 `EvalFile` 等选项，替换版本后若不支持则明确报错，不静默降级。
- **复盘耗时**：每手两次搜索，一局 80 手约 160 次计算。300k 节点下单次通常不到 1 秒，整体可接受；若过慢可下调复盘节点数。
- **中文记谱边界**：通过“生成后匹配”避免解析歧义，但生成器本身需覆盖同列多子；测试中重点覆盖兵、炮。
- **规则简化**：长将判和而非判负，与正式竞赛规则存在差异，已在文档中明示。
- **无 GUI**：棋盘为纯文本，宽度固定约 40 列，适合终端阅读；不做自适应缩放。
